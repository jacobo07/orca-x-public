<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| phone -> broker (host.wake.request) | the phone chooses which paired host receives a wake request |
| broker refusal -> phone state | a refusal code enters phone state that also holds revocation latches |
| session memory -> device storage | answers could outlive the session they prove |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-21 | Spoofing | wrong-host wake: the request goes to the target, another broker or a stale route | high | mitigate | route recomputed at press time by composeHostWakeRoute; sent only on the routed broker's own client; tracer row asserts one send on A, none on T |
| T-21-22 | Spoofing | ambiguous broker resolved by recency in the hook | high | mitigate | the hook never picks; planHostWakePress returns null unless the composer routes |
| T-21-23 | Denial of service | a wake refusal (wake_device_revoked) trips the device-revocation latch and locks the phone out of the broker | high | mitigate | refusal stored as a wake state; no import of the latch; predicate-false row |
| T-21-24 | Tampering | persisted broker answers or wakes act as evidence later | medium | mitigate | React state only; storage-token row over the new sources; saveHomeSnapshot unchanged |
| T-21-25 | Denial of service | a free-running poll per card | medium | mitigate | no timer; focus and press re-reads only; timer-token row |
| T-21-26 | Information disclosure | MAC on the phone | medium | mitigate | the phone stores targetId, label and hostKey only (21-01 projection) |
</threat_model>
